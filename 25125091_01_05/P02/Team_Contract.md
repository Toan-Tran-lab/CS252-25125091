## 5. Work Process & Standards
* **Task Management Tool:** GitHub Projects (Kanban board: *To Do $\rightarrow$ In Progress $\rightarrow$ In Review $\rightarrow$ Done*).
* **Branching Strategy:**
  * Direct commits to the `main` branch are strictly prohibited.
  * Branch naming convention: `<task-type>/<short-description>` (e.g., `feat/ast-parser`, `docs/team-contract`, `test/coverage-eval`).
* **Commit Conventions (Conventional Commits):**
  * `feat: ...` (new feature)
  * `fix: ...` (bug fix)
  * `docs: ...` (documentation/reports)
  * `test: ...` (adding/updating tests)
* **Code Review & Pull Requests (PR):**
  * Every PR merged into `main` must include a clear description and requires approval from at least one peer reviewer.
* **Quality Standards:**
  * Code must adhere to PEP 8 standards, pass all automated unit tests (`pytest`), and include descriptive docstrings.
  * Documentation must be written in clear Markdown format with reproducible instructions.

---

## 6. Governance & Conflict Resolution
* **Decision Making:** Consensus is prioritized. In the event of disagreements, decisions will be resolved by a simple majority vote (> 50%). In case of a tie, the Team Leader holds the deciding vote.
* **Conflict Resolution Steps:**
  1. *Step 1:* Direct, constructive, and respectful peer-to-peer discussion between the involved members.
  2. *Step 2:* The Team Leader mediates to identify a balanced technical solution.
  3. *Step 3:* If unresolved internally, the Team Leader will consult the Teaching Assistant (TA) or Course Instructor for guidance.
* **Accountability & Consequences:**
  * *First Violation (unexcused absence / missed deadline):* Internal reminder and verbal warning.
  * *Second Violation:* Formal warning and assignment of supplementary support tasks.
  * *Third Violation (persistent neglect / non-contribution):* Formal team meeting, documentation of non-contribution, reduction of the member's contribution percentage in the final project report, and formal notification to the instructor.

## 7. Academic Integrity & AI Policy
* **Permissible AI Use:** Generative AI tools (ChatGPT, Gemini, Claude, GitHub Copilot) are permitted as engineering aids for brainstorming, syntax lookup, code optimization, and drafting documentation.
* **Attribution & Accountability:**
  * Submitting unverified or copy-pasted AI-generated code without full comprehension is strictly forbidden.
  * All code integrated into the repository must be locally executed, tested, and validated with unit tests by team members.
  * Each member must maintain an AI usage log (tool, prompt, purpose, and verification method) in their personal reflection report.
